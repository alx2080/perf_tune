# Performance Tune

Кастомная интеграция Home Assistant для систем с тысячами быстро меняющихся
сущностей (SCADA, Modbus/MQTT/S7 на тысячи точек). Убирает две причины тормозов:

1. **Браузер не успевает за потоком изменений.** Интерфейс получает каждое
   изменение каждой сущности отдельным сообщением, независимо от открытой
   страницы. При сотнях изменений в секунду страницы тормозят, а HA рвёт
   соединение («Client unable to keep up with pending messages»).
2. **Периодические «подвисания» всего HA на 1–1,5 с.** Это полная сборка мусора
   Python. Каждое изменение состояния оставляет цикл ссылок Event ↔ Context,
   который освобождает только она. Свой цикл на каждое сообщение добавляет и paho-mqtt.

Замер на HAOS 2026.11.2, 3 vCPU: 15 000 точек (Modbus + MQTT + S7), каждая меняется раз в секунду.

| | Без интеграции | С интеграцией |
|---|---|---|
| Интерфейс | 6–10 кадр/с, задержка до 2 с, разрывы | 32 кадр/с, 5–50 мс |
| Подвисания ядра ≥ 0,5 с | ~15 в минуту по 1,3–1,6 с | 0 (макс. 72 мс) |
| Время на сборку мусора | ~35 % | ~3 % |
| CPU ядра HA | 25–34 % | 18–20 % |

## Исправления

Каждое включается в параметрах интеграции.

| Исправление | Что делает |
|---|---|
| **ws_batch** | Подменяет WebSocket-команду `subscribe_entities`. Изменения копятся и раз в 0,5 с уходят в браузер одним сообщением, по каждой сущности только последнее. Формат прежний, фронтенд не меняется. |
| **gc_freeze** | Через минуту после запуска делает `gc.collect(); gc.freeze()`. ~2 млн долгоживущих объектов перестают сканироваться при каждой полной сборке. |
| **break_cycles** | После `state_changed` обнуляет `context.origin_event` у сущностей с заданными префиксами (по умолчанию `sensor.`). Event, Context и State освобождаются подсчётом ссылок, без полной сборки. `origin_event` использует журнал в реальном времени для подписи «вызвано …». Весь код HA на другие применения не проверялся: если появятся странности, выключите это исправление первым. |
| **patch_paho** | Заменяет `paho.mqtt.matcher.MQTTMatcher.iter_match` эквивалентной версией без самоссылающегося замыкания. Перед заменой проверяет совпадение результатов на наборе топиков. |

## Безопасность при обновлениях HA

Интеграция трогает внутренности Home Assistant и paho-mqtt. Поэтому:

- **Проверка перед включением.** Каждое исправление сначала проверяет, что нужные функции и атрибуты на месте и выглядят как ожидается.
- **Если обновление их изменило,** исправление **не включается**. HA работает как обычно, в «Настройки → Ремонты» появляется сообщение, а в атрибутах сенсора «Активные исправления» видна причина.
- **Откат.** При выключении или удалении интеграция возвращает всё как было без перезапуска. Проверено перезагрузкой интеграции, удаление отдельно не проверялось. Исключение — уже открытые вкладки браузера: они получат обычную отправку после переподключения.

## Диагностические сенсоры

Устройство **Performance Tune**, сенсоры обновляются раз в 10 с, все значения за последнюю минуту:
- **сборка мусора:** доля времени, максимальная пауза, число полных сборок;
- **задержка цикла событий:** максимальная;
- **число замороженных объектов;**
- **активные исправления:** `4/4`, в атрибутах статус каждого.

Сервисы:
- `perf_tune.garbage_report` — какие объекты попадают в циклический мусор (поиск источника пауз);
- `perf_tune.freeze` — заморозить объекты сейчас.

Оба доступны только администраторам. Отчёт ограничен 10 секундами: на это время мусор копится в памяти.

## Установка

**HACS:** «⋮ → Custom repositories», репозиторий `https://github.com/alx2080/perf_tune`, тип Integration. Затем **Download** и перезапуск HA.

**Вручную:** скопируйте `custom_components/perf_tune` в `config/custom_components/` и перезапустите HA.

Затем «Настройки → Устройства и службы → Добавить интеграцию → Performance Tune».

## Чего не делать

Не поднимайте порог полной сборки мусора (`gc.set_threshold(…, …, 1000)`). Подвисания исчезнут, но циклический мусор начнёт копиться: в тесте память ядра выросла с 2 до 6,5 ГБ за 3 минуты.

## Ограничения

- Проверено только на Home Assistant 2026.11.2 и на тестовом стенде; длительной (сутки и более) проверки не было.
- Задача **ws_batch** — разгрузить браузер, но рисовать страницу, на которой тысячи значений, всё равно тяжело. Используйте дашборды по 50–100 точек.
- Если интеграции выдают больше ~15 000 изменений в секунду, упор в однопоточный цикл событий HA остаётся. Помогает уменьшение числа изменений: зона нечувствительности, округление, более редкий опрос.
