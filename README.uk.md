# Performance Tune

[English](README.md) | **Українська**

Користувацька інтеграція Home Assistant для систем із тисячами об'єктів, що швидко змінюються (SCADA, Modbus/MQTT/S7 на тисячі точок). Усуває дві причини гальмування:

1. **Браузер не встигає за потоком змін.** Інтерфейс отримує кожну зміну кожного об'єкта окремим повідомленням, незалежно від відкритої сторінки. За сотень змін на секунду сторінки гальмують, а HA розриває з'єднання («Client unable to keep up with pending messages»).
2. **Періодичні «зависання» всього HA на 1–1,5 с.** Це повне збирання сміття Python. Кожна зміна стану залишає цикл посилань Event ↔ Context, який звільняє лише воно. Свій цикл на кожне повідомлення додає й paho-mqtt.

Вимірювання на HAOS 2026.11.2, 3 vCPU: 15 000 точок (Modbus + MQTT + S7), кожна змінюється раз на секунду.

| | Без інтеграції | З інтеграцією |
|---|---|---|
| Інтерфейс | 6–10 кадрів/с, затримка до 2 с, розриви | 32 кадри/с, 5–50 мс |
| Зависання ядра ≥ 0,5 с | ~15 на хвилину по 1,3–1,6 с | 0 (макс. 72 мс) |
| Час на збирання сміття | ~35 % | ~3 % |
| CPU ядра HA | 25–34 % | 18–20 % |

## Виправлення

Кожне вмикається в параметрах інтеграції.

| Виправлення | Що робить |
|---|---|
| **ws_batch** | Підміняє WebSocket-команду `subscribe_entities`. Зміни накопичуються й раз на 0,5 с надходять у браузер одним повідомленням, для кожного об'єкта лише останній стан. Формат той самий, фронтенд не змінюється. |
| **gc_freeze** | Через хвилину після запуску виконує `gc.collect(); gc.freeze()`. Близько 2 млн довгоживучих об'єктів більше не скануються під час кожного повного збирання. |
| **break_cycles** | Після `state_changed` обнуляє `context.origin_event` в об'єктів із заданими префіксами (типово `sensor.`). Event, Context і State звільняються підрахунком посилань, без повного збирання. `origin_event` використовує журнал у реальному часі для підпису «викликано …». Увесь код HA на інші застосування не перевірявся: якщо з'являться дивацтва, вимкніть це виправлення першим. |
| **patch_paho** | Замінює `paho.mqtt.matcher.MQTTMatcher.iter_match` еквівалентною версією без замикання, що посилається саме на себе. Перед заміною перевіряє збіг результатів на наборі топіків. |

## Безпека під час оновлень HA

Інтеграція зачіпає внутрішній устрій Home Assistant і paho-mqtt. Тому:

- **Перевірка перед увімкненням.** Кожне виправлення спершу перевіряє, що потрібні функції й атрибути на місці та мають очікуваний вигляд.
- **Якщо оновлення їх змінило,** виправлення **не вмикається**. HA працює як зазвичай, у «Налаштування → Ремонти» з'являється повідомлення, а причину видно в атрибутах сенсора «Активні виправлення».
- **Відкат.** Під час вимкнення або видалення інтеграція повертає все як було без перезапуску. Перевірено перезавантаженням інтеграції, видалення окремо не перевірялося. Виняток — уже відкриті вкладки браузера: вони повернуться до звичайного надсилання після перепідключення.

## Діагностичні сенсори

Пристрій **Performance Tune**, сенсори оновлюються раз на 10 с, усі значення за останню хвилину:
- **збирання сміття:** частка часу, найдовша пауза, кількість повних збирань;
- **затримка циклу подій:** максимальна;
- **кількість заморожених об'єктів;**
- **активні виправлення:** `4/4`, в атрибутах статус кожного.

Дії:
- `perf_tune.garbage_report` — які об'єкти потрапляють у циклічне сміття (пошук джерела пауз);
- `perf_tune.freeze` — заморозити об'єкти зараз.

Обидві доступні лише адміністраторам. Звіт обмежено 10 секундами: на цей час сміття накопичується в пам'яті.

## Встановлення

**HACS:** «⋮ → Custom repositories», репозиторій `https://github.com/alx2080/perf_tune`, тип Integration. Потім **Download** і перезапуск HA.

**Вручну:** скопіюйте `custom_components/perf_tune` у `config/custom_components/` і перезапустіть HA.

Потім «Налаштування → Пристрої та служби → Додати інтеграцію → Performance Tune».

## Чого не робити

Не піднімайте поріг повного збирання сміття (`gc.set_threshold(…, …, 1000)`). Зависання зникнуть, але циклічне сміття почне накопичуватися: у тесті пам'ять ядра зросла з 2 до 6,5 ГБ за 3 хвилини.

## Обмеження

- Перевірено лише на Home Assistant 2026.11.2 на тестовому стенді; тривалої перевірки (доба й більше) не було.
- Завдання **ws_batch** — розвантажити браузер, але малювати сторінку з тисячами значень однаково важко. Використовуйте панелі на 50–100 точок.
- Понад ~15 000 змін на секунду межею лишається однопотоковий цикл подій HA. Допомагає зменшення кількості змін: зона нечутливості, округлення, рідше опитування.
